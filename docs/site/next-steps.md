# Next validation steps

The scalar static transfer and stationary RIN comparisons are complete for their recorded configurations. The fixed ANN and trained CNN retain their separate numerical-reference comparisons. See the archived evidence under `validation/release_evidence/` for counts, settings and scope.

1. **Reproduce the current software benchmark on the Windows computer.** Run `python benchmark_execution.py --count 360 --blocks 5 --warmups 1` in the updated folder. Keep the complete new result directory. It compares current waveform and symbol execution; it does not rerun the native scalar experiment. Use that local result for a current-machine performance statement.
2. **Validate native input and weight transitions.** Start from the saved scalar INTERCONNECT working copy. Turn stochastic sources off. Keep the same DAC, extinction, responsivity, capacitance, gain and bias. Apply a declared time-dependent input, then a declared time-dependent weight in separate experiments. Capture the drive, both powers, three currents, capacitor, preactivation and both outputs with their timestamps. Compare measured transition samples and adjacent interval integrals, rather than fitting away a delay.
3. **Characterize accumulation and reset.** Define symbol and reset timing explicitly. Test a positive product, a negative product and zero weight across at least two accumulation windows. Record the initial state and reset interval. This requires an explicit reset circuit/model; the present ideal per-call capacitor reset does not validate a physical reset switch. Fix acceptance tolerances before collecting a campaign, following the principle used in the RIN comparison.
4. **Expand the stochastic operating range.** Vary optical power, input, weight and sample rate in a planned grid. Add receiver bandwidth, dark-current and thermal conditions separately. Use a phase-sensitive observable to validate linewidth effects. Keep the shared-source branch covariance and whole-trial uncertainty.
5. **Evaluate noisy ANN/CNN inference.** Freeze weights and test split. Report layer errors, converter range failures, output changes and task accuracy across independent realizations. Keep a numerical implementation as the reference. Any noise-aware retraining is a separate experiment.
6. **Build a hardware cost model.** Include conversion, bias/control, memory movement, reset, readout, nonlinear operations, device count and energy. The proposed ADC-ROM sigmoid and compare/select pooling need their own implementation evidence. Optical arithmetic alone does not establish a complete optical CNN.

Native step/reset and noisy-network data have not been collected by this software release. Its report must state these as planned tests. The earlier RIN zero/missing records remain historical evidence, and normal fresh seed replays do not retrospectively identify their cause.

Update the report only for a meaningful implementation change or new result, with the matching settings, source/data version, uncertainty and limitations. Keep old measurements as dated observations rather than silently replacing them.
